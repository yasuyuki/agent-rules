title: 作業正本と再開情報の受渡し
summary: 作業正本・運用文書・証拠から再開し、全体現在地ファイルを退役する。環境間の保存・配送・受領・受入を区別する。
---

委任された作業の目的・許可・受入条件は指定 Issue の本文、結果・証拠・残件は同 Issue を正本にする。
追加・訂正は有効な契約へ統合し、過去コメントや元チャットから再構成させない。既存の成果物・
登録 branch・共有先を必要範囲だけ照合し、共有用変更の前に対象 remote との履歴関係を確認する。
指定タスクがなければ既存の作業記録を使い、通常作業に共有 Issue や受領確認を一律に要求しない。

## 再開情報の所有先

workspace全体の現在地を集める `HANDOFF.md` は作成・更新・探索しない。
別名の全体現在地ファイル、常時更新する作業一覧、同じ情報の二重の正本を作らない。
依頼と対象repoのREADME・明示設定から、その作業の正本と保存先を確認する。
着手後も同じ正本に残作業・本人保留・受入条件を残し、有効な結果へ本文から到達できるようにする。

- 恒久的な手順と操作境界は、所有するREADME・運用文書・ruleへ置く。
- 検証条件・観測・成果物の所在と保持条件は、その作業の証拠・復旧記録へ置く。
- Git・branch台帳・配置設定から再取得できる値は、現在地の文章へ転記しない。
- 復元できない中断理由・判断・次の操作だけを再開情報として残す。同一環境だけの非共有情報は
  既存の作業別private記録へ置き、不足する場合だけ専用記録を作る。所有者と取得先を作業正本に
  結び付け、ローカル保存を他環境への配送やバックアップの完了としない。

再開判断が変わったときだけ担当する保存先を更新して再読する。無関係な状態は保つ。
完了履歴はcommit・完了済みIssue・証拠へ残し、古い次工程を除く。別作業のdirtyを理由に
必要な情報を唯一の未commitファイルへ残し続けない。担当sourceを検証・commitし、push規則に従う。
その場で終わる作業や読み取り確認に再開記録を一律に要求しない。

その場で直さない欠陥を記録するのは、明示された記録要求、必須成果・データ保護への影響、または
人間の監視・承認待ち・反復操作を含む重大な回復負担がある場合だけとする。未観測だけで到達不能と
せず、既存防御を除いた影響も考慮する。既存の指定 Issue を再利用し、なければ対象repoのREADME・明示設定が指定する
台帳または既存 `ISSUES.md` を使う。いずれもなければ
`ISSUES.md` に症状・場所・再現条件を残す。重大表示はデータ破壊・リリース阻害に限る。
書込み不能なら担当作業のprivate記録に未保存内容を保全し、配送未完了を報告する。直した問題は close / 除去し、着手や進捗を二重記録しない。

## 既存HANDOFFの退役

原情報をhash付きでprivateに保全し、未共有の判断・本人保留・保持物の所在を目的別の保存先へ
移して再読する。全文を別名の現用記録にしない。古い状態は現在の正本・機械状態で照合する。
ファイルを参照・生成するrule・receiver・同期設定はownerの正規入口で移行する。受信情報を
先に保存し、通常起動がファイルを要求・再生成しないことを確認した環境だけで削除する。
固定版・封印・認証・権限境界を緩めない。未受入環境・取得不能情報は共有作業の未完了に残す。

環境やツールをユーザーへ引き渡すときは、明示された版指定・更新保留がない限り、対象ツールを
引き渡し時点の公式配布元の最新安定版へ更新する。更新の依頼がないことや既存版での起動成功を、
旧版を残す理由にしない。ユーザーが使うhost・user・HOME・PATHと実際の起動入口で、解決される
実行ファイルと版数を確認し、配布元の最新版との一致と必要な起動動作を検証してから引き渡す。
明示された固定版や封印済みruntimeはその境界に従う。更新や最新確認ができなければ未完了として
理由を伝え、最新版を確認済みとは扱わない。

## 環境間の引継ぎ

共有先は依頼・対象 Issue・対象作業の設定や README から特定し、既存タスクを再利用する。
directoryの近さや任意の HOME 探索から推測しない。不明なら配送先未確定とし、必要情報を保全する。
元環境の会話やファイルを読めなくても再開できるよう、共有正本に次を必要範囲で揃える。

- 目的・許可範囲・現在地・残作業・必須受入・返却先
- 実行環境と必要能力、送り手で実行できない理由、依存関係、禁止操作と保持する状態
- repository/revision、成果物・証拠と参照文書の取得先、実在する入口・cwd・入力

元依頼を取得できず追補だけがある場合は、有効な契約を単独で読める本文へ統合する。
未 push の commit や一時 path を唯一の取得先にしない。工程・能力が異なる場合は利用可能な
`classify-work` を使えるが、分類を接続・転送・実行許可としない。

保存後は共有正本と必要な取得経路を再読し、参照を受取側への依頼または最終応答に示す。
許可済みの直接配送を使い、自動発見を仮定しない。書込み失敗時は元情報を保全し、既存中継経路が
あれば受取環境とそのまま渡せる依頼を示す。人間による中継は `human-handoff` に従う。
経路がなければ具体的な不足と未配送を明示する。共有先未確定なら決定・保存も残作業に含める。

未配送、共有先保存済み/中継依頼提示済み、受領済み、必須受入達成を区別する。
送り手の再読・通知や合成試験を受取側の取得・実行・受入とみなさない。必要な保存・通知後は
未受領・未適用を明示してセッションを区切ってよいが、必須受入が残る作業全体は完了にしない。
受取側は既存識別子の契約と成果物を確認し、受領・実行結果・残件を同じ正本へ返す。
再通知による Issue 重複や実施済み操作の無条件な再実行をしない。本人指定の保留を守る。

隔離・認証・権限・公開範囲を変更して配送を成立させない。私的 HANDOFF 全文、資格情報、非共有の
path・情報を診断や引用にも漏らさず、必要な共有可能情報だけを渡す。ignore 方針を変えず、
local-data を commit しない。元情報の削除・参照への置換は対応情報の保全・共有確認後に行う。
安全な経路がなければ情報を保持して未配送とする。保存済みの結論・証拠は返却先ごとに再生成しない。
