summary: workspace内の再開は最寄りのHANDOFF。環境間の未完了作業は取得可能な共有タスクを正本とし、保存・配送・受領・受入を区別する。

同じworkspaceでは、会話の文脈を失っても `HANDOFF.md` から再開できる状態を保つ。
別環境で必要な未完了作業には、末尾の「環境間の引継ぎ」を適用する。

環境やツールをユーザーへ引き渡すときは、明示された版指定・更新保留がない限り、対象ツールを
引き渡し時点の公式配布元の最新安定版へ更新する。更新の依頼がないことや既存版での起動成功を、
旧版を残す理由にしない。ユーザーが使うhost・user・HOME・PATHと実際の起動入口で、解決される
実行ファイルと版数を確認し、配布元の最新版との一致と必要な起動動作を検証してから引き渡す。
明示された固定版や封印済みruntimeはその境界に従う。更新や最新確認ができなければ未完了として
理由を伝え、最新版を確認済みとは扱わない。

**対象は作業ディレクトリから上へ辿って最初に見つかる `HANDOFF.md` であり、1つの workspace に
1つだけ置く。** リポジトリごとに作らない。複数リポジトリが1つのシステムとして運用されていても、
正本の選定、他リポジトリへのスタブ設置、システム一覧の表は行わない。**位置が対象を決めるので、
どれが正本かの判定は不要である。** 同じ事実を2箇所へ書けば必ず片方が古くなる。

上へ辿って見つからないときだけ、workspace root に新規作成する。配下のリポジトリを独立した
作業対象として切り出すときだけ、そのリポジトリ root へ新しく置く。上へ辿る規則が自動的に
そちらを選ぶので、既存の対象へ「こちらを見よ」と書き足さない。

`HANDOFF.md` は作業ログではなく現在地である。原則として次の4節だけを使い、完了した作業、
古い次工程、不要な注意は削除する。

```
# HANDOFF: <workspace>  (最終更新 YYYY-MM-DD)
## 現在地
## 次にやること
## 途中状態
## 注意
```

- `現在地` は動作する範囲と未完了事項、`次にやること` は優先順の具体的操作、`途中状態` は
  未コミット変更、退避、一時設定、中断中の検証、`注意` は知らないと壊す事項だけを記す
- 対象が複数のリポジトリやサブプロジェクトを含むときは、各節の中で行または段落を分けて書き、
  節そのものを増やさない
- 複数ブランチを並行して維持するときだけ、ブランチごとの節を追加し、並行が終われば基本4節へ戻す
- 状態ファイル、git status、ツール出力から再取得できる値は記録せず、必要なら再取得コマンドと併記する
- 手順や恒久的知識は README または docs、設計判断はコードまたは設計文書、長いログと計測値は
  専用ファイルへ置く

その場で直さない具体的な欠陥は、`HANDOFF.md` と同じ directory の未解決台帳に1件残す。
台帳は次の順で決める。

1. その directory に `ISSUES.md` があれば、そこに1件1行で書く。形式は
   `- [!] <症状> — <場所: file:line またはサブシステム>。<再現条件>` とし、`[!]` は放置すると
   データを壊すかリリースを止めるものだけに使う
2. 無ければ、同じ directory の README が GitHub Issues を未解決台帳と書いていれば、その
   repository に Issue を1件作る。title は症状、body は場所と再現条件。`[!]` 相当は
   label `critical`。書けなければ `HANDOFF.md` の途中状態へ1行残し、`ISSUES.md` は作らない
3. どちらも無ければ `ISSUES.md` を作って 1 へ戻る

直した問題は台帳から除く（GitHub なら close）。着手すると決めた問題は
`HANDOFF.md` の「次にやること」へ移し、GitHub Issue は open のままにする。
進捗本文を両方に置かない。環境間の共有正本への参照は残す。

再開に必要な現在地、未完了、判断、注意が変わったときは、最終応答前に `HANDOFF.md` を更新して
読み返す。長い作業では中断や context の喪失に備え、意味のある区切りでも更新する。
読み取りだけの確認、既に記録済みの結果、完了して恒久文書や commit で分かる変更のために
差分を作らない。既存の無関係な状態は保持し、今回に関係する古い記述だけを整理する。
追跡・ignore 方針を勝手に変えず、local-data store は commit しない。


## 環境間の引継ぎ

最寄りのHANDOFFを選ぶ規則は、別環境からの可読性や配送を保証しない。別環境で必要な
検証・適用・採用・運用確認も対象とし、ローカルへの記録だけで引継ぎ済みにしない。
同一環境で完結する通常作業に共有Issueや受領確認を一律に要求しない。

**共有タスクを環境間作業の正本にする。** 依頼、対象Issue、対象作業の明示された設定・README
から共有先を決め、既存タスクを再利用する。HANDOFFの位置や任意のHOME探索から推測しない。
特定できなければ配送先未確定とする。各環境のHANDOFFには正本の参照と環境固有の途中状態を
置き、着手や送り手工程の終了を理由に必要情報を共有先からローカルだけへ移さない。

受取側が元環境の会話・ファイルを読めなくても再開できるよう、必要な目的・許可済み範囲・
現在地・残作業、環境/能力と送り手で実行できない理由、repository/revision、成果物と証拠の
取得先、依存関係・実在する入口・cwd・入力、禁止操作・保持する状態・受入条件・返却先を渡す。
参照文書の本文と成果物の取得経路を確認する。追補しかなく元依頼を取得できなければ、
元依頼を共有・同梱するか有効な指示を単独で読める本文へ統合する。未pushのcommitや一時pathを
唯一の取得先にしない。元環境にしかない成果物は未配送とし、取得・受渡しの残作業を明記する。
工程/能力が異なるときは既存の `classify-work` を用い、分類を接続・転送・実行許可にしない。

共有先へ保存したら再読して内容と必要な取得経路を確認し、その参照を受取側への依頼または
最終応答にも出す。既存の直接配送は許可済み範囲で使い、自動配送・発見の存在を仮定しない。
書込み失敗時は元情報を保全する。利用可能な中継経路があれば、受取環境とそのまま渡せる依頼を
最終応答へ出す。共有先未確定なら正本の決定・保存も残作業として渡す。読めないローカルpathや
存在しない保存先だけを案内しない。経路がなければ具体的な不足と配送不能を明示する。
ユーザーが別環境agentへ中継する操作もユーザー作業であり、`human-handoff` に従って提示する。

未配送、共有先保存済み/中継依頼提示済み、受領済み、必須受入達成による完了を区別する。
送り手の再読や通知を受取側の取得・受領・実行とみなさない。発行と必要な通知が終われば
未受領・未実行を残して送り手のセッションを区切ってよく、独立して可能な他作業は続けてよい。
受取側は既存識別子の依頼・成果物・結果を確認し、受領、実行結果、残作業を共有正本へ返す。
再通知でIssueを重複作成したり実行済み操作を無条件に再実行しない。能力不足、本人指定の保留、
未実施の必須受入が残る間は、送り手の完了や合成試験の成功を作業全体の完了にしない。

隔離境界、認証、権限、公開範囲を変更して配送を成立させない。私的HANDOFF全体や資格情報を
共有せず、渡せる必要情報だけを選ぶ。共有する説明・引用・診断欄にも同じ制約を適用し、
非共有の私的pathや情報を根拠の引用として漏らさない。ignore方針を変えず、local-dataを共有のためにcommitしない。
元情報の削除・参照への置換は対応情報の保全・共有を確認してから行う。安全な共有先や経路が
使えなければ情報を保持して未配送とする。
