Codex では共通の委譲規則に加え、起動前に作業の難度、検証可能性、必要な文脈を見て
モデルを選ぶ。目標は受け入れ条件を満たすまでの総コストであり、入力・推論・出力に加え、
再試行、リードの再調査と統合も考慮する。単価の安さだけで選ばない。

## 振り分け

- Astra のリードは、要件の曖昧さの解消、密に結合した難所、統合と最終判断を自分で扱う。
  委譲のためだけに設計を作り直させない。小さな作業は起動せず直接完了する。
- `fast-worker` / GPT-5.6 Luna: 検索、分類、文書、定型編集など、範囲が明確で結果を容易に
  確認できる独立作業。未知の設計判断や重大な安全性判断は渡さない。
- `implementer` / GPT-5.6 Terra: 仕様と不変条件が決まった実装。
  `reviewer` / Terra: diff と検証結果に基づく独立した正しさの確認。
- `designer` / GPT-5.6 Sol: 独立した比較検討が必要な複雑な設計。リードと同じ分析を
  繰り返すためには起動しない。
- GPT-6 Astra の子: 独立して切り出せる難しい推論・診断・設計で、下位モデルの手戻りを
  含めると直接 Astra に任せる方が有利と判断できる場合。重大な未解決リスクについて
  独立した検証が必要な場合も候補とする。最初から難しいと分かる仕事を安い順に試さない。

これは起動時の選択方針であり、役割名のモデル設定を書き換えるものではない。
実環境の利用可能モデル、固定された役割のモデル・推論設定・sandbox と上位指示を優先する。
モデルを指定できる汎用役割で Astra を使う場合も、読み取り専用の分析か実装かを依頼に
明記する。固定役割の制限を別役割で迂回しない。利用不能ならリードで処理するか、
要件を満たせる利用可能な役割を選ぶ。

## 起動と再試行

- 独立作業には必要な目的・証拠の場所・制約を渡す。全履歴が不要なら `fork_turns="none"`
  と自己完結した依頼を使う。モデル override と全履歴 fork が両立しない実装では併用しない。
- モデル選択が可能な起動では対象モデルを明示し、意図しない高価な親モデル継承を避ける。
  固定役割では設定済みモデルを使う。推論量は役割の既定から始め、難度に根拠があるときだけ
  変更する。常に最大へ上げない。
- 関連する続きは既存 agent を再利用する。同じ調査をリードと子で重複実行しないが、
  リードによる実物・検証結果の確認は省かない。
- 不十分な結果は、情報不足、検証失敗、推論の難しさを区別する。情報や仕様を補えば解ける
  場合は補い、能力不足なら残る論点と証拠をリードまたは適切なモデルへ渡す。
  同じ依頼の再送や、Luna → Terra → Sol → Astra の機械的な全段階実行はしない。
- 完了した仕事を比較用に別モデルで再実行しない。実作業で取得できる利用量、手戻り、
  受け入れ結果があれば次の選択に使う。API 単価を Codex の請求額や quota と同一視せず、
  測定なしに節約率や最適性を断定しない。
